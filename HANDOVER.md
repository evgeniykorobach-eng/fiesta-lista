Этот файл — точка входа для любого ИИ или разработчика, который продолжит работу.

## Что это

Прототип платформы аренды детских праздничных столов и оборудования в Барселоне (Испания).
Бизнес-клиент: семейный мини-бизнес, два администратора (владелец и его брат).
Полное ТЗ на русском диктовал заказчик голосом; ключевые требования ниже.

- Репозиторий: https://github.com/evgeniykorobach-eng/fiesta-lista.git
- Живой сайт (GitHub Pages): https://evgeniykorobach-eng.github.io/fiesta-lista/
- Локальный запуск: `cd <папка> && python3 -m http.server 8787` → http://localhost:8787/
- Стек: чистый HTML/CSS/JS, без сборки, без зависимостей, без бэкенда (пока).

## Главные бизнес-правила (не нарушать)

1. **Всё только на улице**: парки, сады, уличные площадки. Столы домой НЕ сдаются.
   Это позиционирование: главный баннер — сцена праздника в парке.
2. Языки сайта по ТЗ: испанский (основной), каталанский, английский.
   **Русский добавлен временно** (заказчику удобно проверять) — потом удалить.
3. Валюта — только евро (€).
4. Три готовых пакета: BASIC (149 €), STANDARD (249 €), PREMIUM (399 €).
5. Предоплата при бронировании: 50% (настраивается в админке → Цены).
6. Доставка по Барселоне бесплатно, за пределами — платно (тариф в админке).
7. Аренда по времени (не на день): 4/6/8 часов + 1 час на монтаж до и 1 час демонтаж после.
8. Telegram не используется. WhatsApp — основной мессенджер.

## Админка (admin.html)

- Вход: ссылка «Admin» в футере главной → экран PIN. По умолчанию **1234**.
  Смена PIN — кнопка «PIN» в шапке, выход — «Выйти». Защита прототипная (проверка в браузере).
- Разделы: Сводка, Заказы (10 статусов из ТЗ, ✓/✕), Календарь, Склад (статусы + окупаемость),
  Клиенты (CRM из броней + заметки), Цены (пакеты, % предоплаты, тарифы доставки),
  Финансы (расходы с категориями), Реклама (визиты/заявки/конверсия/€ за заявку + UTM-ссылки),
  Журнал действий. Два аккаунта: owner / brother.

## Данные (localStorage — всё живёт в браузере!)

- `fl_bookings` — брони (в т.ч. `utm` — источник рекламы)
- `fl_prices` — цены: basic/std/prem, depositPct, delBCN, delOut (админка → Цены; конструктор и главная читают отсюда)
- `fl_expenses` — расходы (категории, привязка к заказу)
- `fl_crm_notes` — заметки CRM
- `fl_admin_log` — журнал действий админов
- `fl_admin_pin` (дефолт 1234), `fl_admin_auth` (сессия входа), `fl_admin_user` (owner/brother)
- `fl_visits`, `fl_utm` — рекламная аналитика
- `fl_lang` — выбранный язык
- `fl_admin_seed_v1`, `fl_admin_seed_v2` — флаги демо-данных (не удалять, иначе сиды перезапишутся)

**Важно:** данных на сервере нет. Заявка, сделанная на телефоне клиента, НЕ попадёт
в админку на компьютере владельца. Это главное ограничение текущего этапа.

## Как работать с заказчиком

- Русскоязычный, диктует голосом (бывают опечатки распознавания). Отвечать **коротко по-русски**,
  с конкретными ссылками на страницы. Без лишней теории.
- Рабочий цикл: правка → проверка в браузере → `git commit` → `git push` → GitHub Pages обновляется ~30 сек.
- Каждое изменение проверять вживую (открыть страницу, прокликать).
- Не предлагать Telegram. Не делать мобильные приложения (по ТЗ — только мобильная версия сайта).
